# 知识库维护规范

适用于 `ai-collaboration-handbook/` 及其子目录；不据此改动同仓库的其他项目。用户当前明确指令优先于本文件。

## 开始任务

1. 在仓库根目录检查 `git status --short --branch` 和已有差异，保留他人的修改与未跟踪文件。检查上层适用的 `AGENTS.md`。
2. 依次读本文件、`PROJECT_STATUS.md`、`SUMMARY.md`，再读相关主题、提示词和来源登记。正式决策以文件为准，不依赖旧会话记忆。
3. 明确目标、材料能否完整访问、准备修改哪些文件。用户要求先规划时，确认之前只做只读检查。

云端 `/workspace/ChatGPT_CodeX` 是长期主维护位置，本项目在其子目录中。Windows 是按需副本。沿用仓库根目录 Git；每个云任务已经隔离，默认使用现有检出，不创建 Git worktree 或嵌套仓库。不得自动进行推送、发布环境或部署。

## 判断内容归属

- 先搜索同义词、术语和现有论点，判断新材料在回答什么问题，而不是按材料标题建文件。
- 已有问题的新证据或例子：整合进原章节，不机械追加。
- 独立问题且有实质内容：新建 `docs/<topic>/`，包括入口和正文；同步总目录。
- 多主题共享的方法：优先链接已有 `docs/shared/`。确需抽取时保留原位置的导航并修复链接，避免两份正文平行维护。
- 规划只放项目状态；不创建冒充完成内容的空白章节。

## 写作与信息保真

主要使用中文，重要术语首次出现附英文；固定用“深度阅读（Deep Reading）”，说明 S001 的“研究性阅读”属于相同层级的原始命名，不声称是统一学术分类。以背景与问题、概念与分析、方法、案例、边界及延伸组织内容，不机械套模板。

来源归属与核验状态是两个维度，遵循 [来源核验规范](docs/shared/source-verification.md)。每个主要章节说明依据来自 S001 哪部分、哪些是编辑新增。原讨论中的“研究表明”必须另核对文献；“作者说是事实”不等于事实已证实。数量、时间、因果结论与适用条件要保持一致。

原始材料保存在 `sources/`，新增材料使用递增 S 编号，登记提供者、接收日期、可访问范围和映射。不得静默润色已归档的原文；格式清理应在整理版完成，必要勘误单独说明。不能读取的图、PDF 公式和补充材料明确记录。避免重复保存用户的私人或敏感内容；需要脱敏或对外公开时先明确范围。

文献使用 R 编号，统一登记于 `sources/references.md`，正文链接到对应条目。记录核验日期、链接、实际访问层级（书目／摘要／全文／失败）与结论边界。无法确认的 DOI、标题或结论不要补写为确定事实。教学例子标明虚构，不填造论文参数和结果。

提示词集中维护在 `templates/`，正文引用而不复制多个版本。提示词须要求来源定位、信息类型区分和不可读范围声明，禁止凭空生成页码与引用。

## 冲突与不确定性

发现矛盾时先检查是否因任务、定义、发表时间或适用范围不同。实质冲突记录在 `PROJECT_STATUS.md`：旧观点及来源、新观点及来源、影响位置、建议处理、待用户决定事项。在确认前不静默覆盖旧观点；必要时并列标注争议，其余独立工作可继续。

可直接修复排版、链接等不改变含义的问题。重要论点的合并、迁移或删除应在来源映射或更新日志留下去向。区分“已整理”“待验证”“待展开”“规划”；已整理只表示编辑完成。

## 同步与质量检查

改动后核对：

- 新增、移动和删除是否同步 `SUMMARY.md`、主题入口、交叉链接和工具入口；Markdown 链接含片段时检查标题或显式锚点。
- 核心观点及论证关系是否保留，限定条件、反例、补充材料缺口是否被隐去。
- 外部结论是否有登记来源，访问范围是否准确，案例是否被误写为真实研究。
- 提示词是否有可填写输入、可检查输出和使用边界；不能用“请全面总结”替代查漏程序。
- 更新 `PROJECT_STATUS.md`；重要内容或结构变化写入 `CHANGELOG.md`。首次出现的术语及文件名保持一致。
- 重新检查仓库状态与本项目差异；不回滚用户或其他项目的改动，不引入非必要工具链。

首版为纯文档，无应用启动或依赖安装。用相对链接检查、来源核对和人工内容审查验证，不以“零测试通过”替代文档质量检查。未来只有链接规模或重复劳动确有需要时才加入检查脚本、网站框架等依赖。

## 结束与提交

汇报改动目的、主要文件、检查结果、未决问题及差异。首次新增文件未跟踪时，`git diff` 不显示其正文，应结合文件清单和内容审查，不能称为“无改动”。

**用户审查并明确授权之前不创建提交**。授权提交时只暂存本次同意的文件，不使用可能卷入其他项目或秘密文件的笼统暂存操作。不自动推送。新会话可以使用 README 中的短指令启动日常维护任务。
