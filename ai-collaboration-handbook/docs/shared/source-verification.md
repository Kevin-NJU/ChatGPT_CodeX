# 来源、主张与核验

**成熟度：已整理。** 本文抽取自 [S001 第四部分](../../sources/S001-reading-discussion.md)的横向阅读建议，并补充项目通用的记录规则。规则是编辑建议，不是已被验证的完整事实核查系统。

## 两个维度必须分开

**来源归属**回答“这是谁说的”：原始讨论观点、原作者陈述、外部研究结论、编辑新增分析或教学假设。

**核验状态**回答“目前查到了什么”：已核对、待核实、材料不足。一个观点可忠实来自原讨论，但仍未证实；一篇论文确实存在，也不意味着其中的全部结论已经核验。

在笔记中可使用这样的写法：

> 原作者主张：政策将提高某产业的产出。来源：评论第 3 段。核验状态：仅确认作者如此表述；因果效果尚无独立证据。编辑分析：需要区分政策目标、实际拨款与产出变化。

不要把“模型自信”“多个模型一致”或“多个网页提到”当成独立事实依据。

## 最小核验流程

1. **拆成可核对的主张。** 将“政策成功推动产业快速增长”拆为政策是否出台、是否执行、增长指标、统计时间、因果解释。
2. **返回最近的一手依据。** 查政策正文、统计表、论文方法或原始数据。摘要、报道和评论分别记录，不混称“原始来源”。一手材料仍可能有偏差，不因其身份而免检。
3. **检查可比性。** 日期、样本、地区、分母、币种、单位、测量方式与版本是否一致。预测和实测分开，相关和因果分开。
4. **检查证据独立性。** 追溯转载和引用链；同一新闻稿的十次转载仍是一条证据链。不同意见也可能共享同一数据，或者证据质量并不对等。
5. **记录支持程度。** 直接支持、部分支持、不支持、相互冲突或无法判断，并附可返回的位置和缺口。

对于高后果结论，不足以核实就暂缓据此行动，不用凑齐若干网页替代证据。无须把每篇低风险文章都处理成全面调查，但应标出哪些内容只是线索。

## 来源记录最小字段

| 字段 | 记录内容 |
| --- | --- |
| 主张 | 具体可核对的句子，保留限定条件 |
| 来源及版本 | 作者、标题、日期或版本、可访问链接；私人材料注明访问范围 |
| 原文位置 | 章节、段落起句、图表或 PDF 页码；印刷页与 PDF 页序不同要注明 |
| 核对范围 | 仅书目、摘要、正文指定部分、全文；图片、公式和附件是否可读 |
| 判断与缺口 | 支持程度、存在的反证、尚缺什么 |
| 核验日期 | 信息会变化时尤其必要 |

找不到页码时用章节和短引文定位，不生成貌似精确的页码。页面能打开不等于正文可读；PDF 转文字成功也不保证图表、数学符号或扫描内容完整。

## 横向阅读与 AI 的分工

[R3](../../sources/references.md#r3)记录了专业核查人员离开当前网站、检查外部信息的观察。它支持一种核查方向，不证明任意 AI 搜索都可靠。

AI 可以建议检索词、拆解主张、整理不同解释和引用链；人要检查链接是否真的存在、内容是否支持主张，以及各来源是否独立。没有联网或无法打开链接时，AI 只能提出核验计划，不能报告“已核查”。

## 争议如何处理

先区分事实争议、定义不同、价值判断和未来预测。事实争议寻找可共同检查的材料；价值判断明确所用标准；预测记录假设、时间范围和后续检验点。材料冲突时保留双方来源与适用范围，不机械折中，也不按“各找一篇”制造证据对等。
