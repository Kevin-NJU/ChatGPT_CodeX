# 项目需求分析提示词

## 适用场景

想法模糊，需要在执行前澄清成果与验收。

## 使用前提

提供已有材料及业务限制；允许的分析范围明确。

## 可复制提示词

```text
请基于 [原始想法] 和 [资料路径/链接] 分析项目需求，预期使用者是 [使用者]。
先读适用规范及与此目标相关的状态/决定，区分原始要求、你提出的建议和未知项。
产出：实际问题、目标、非目标、输入、产物、约束、风险、依赖、里程碑和每阶段可观察验收标准。使用具体例子说明达到目标与未达目标的区别。
判断普通对话、ChatGPT Project、Codex/Git 或组合是否必要，并解释边界；不要为可能的未来需求增加当前范围。
对于妨碍正确执行的重大歧义提出具体问题；其他采用合理默认并注明。当前阶段不实现知识正文或代码，仅允许更新 [分析记录路径] 及规范要求的任务日志；若要求全只读，在回复提供待写记录。
结尾列出可执行的下一步与尚需人决定的事项，不把计划写成已完成。
```

## 替换变量

原始想法、资料路径/链接、使用者、分析记录路径。

## 预期输出

可审查的范围、阶段与验收矩阵、少量必要问题。

## 注意事项

不要承诺没有证据的工期、平台能力或预算。

相关规则见 [指令设计](../docs/05-instructions-prompts.md) 和 [本库维护](../docs/09-maintaining-this-guide.md)。
