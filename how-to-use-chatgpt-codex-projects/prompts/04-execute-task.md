# 项目任务执行提示词

## 适用场景

已有明确目标，需要端到端落实。

## 使用前提

提供目标、输入位置和授权边界。

## 可复制提示词

```text
请完成 [任务目标]，输入为 [资料/文件/版本]，验收标准是 [可观察结果]。
只允许修改 [允许路径]；禁止变动 [保护范围]。先检查适用指令、工作区和有关状态/决定，多阶段先列简短计划。
在现有体系内做必要修改，遇到错误先诊断并修复本次范围内的问题，再复验；继续至验收完成或出现具体外部阻塞，不停在方案或首版生成。
产品功能采用可靠来源并记录核验范围；未经执行的操作、未访问的资料和未运行的检查必须明示。
提交前检查新增文件正文、内部链接、索引、内容/功能、敏感信息及差异范围；验证要对应本次结果，不为简单修改扩展无关检查。
按本项目规范追加一次用户任务日志，并判断 STATUS、CHANGELOG、DECISIONS、ROADMAP、SOURCES 是否有必要更新；避免重复复制事实。
Git 授权：[授权范围]。最终按任务目标、执行结果、文件变更、验证情况、未解决问题、下一步建议报告；涉及 Git 写实际分支/提交/推送/PR。
```

## 替换变量

任务目标、资料/文件/版本、可观察结果、允许路径、保护范围、授权范围。

## 预期输出

符合验收的产物、真实验证和任务记录。

## 注意事项

将必要日志路径包含在允许路径内；权限与命令审批仍受实际环境控制。

相关规则见 [指令设计](../docs/05-instructions-prompts.md) 和 [本库维护](../docs/09-maintaining-this-guide.md)。
