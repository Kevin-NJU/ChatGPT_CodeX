# 本项目的持续工作约定

仅适用于 `how-to-use-chatgpt-codex-projects/` 及子目录。当前用户明确指令优先；系统、开发者指令和执行权限仍须遵循。这是本项目管理约定，不是所有 Codex 项目的产品默认行为。

## 执行前

- 在仓库根目录查看 `git status --short --branch`、已有差异及适用的上层 AGENTS.md；保留他人的修改、未跟踪文件和提交。
- 确认目标、可修改路径和验收标准。默认仅修改本目录，不修改兄弟项目；根目录导航改动须先说明理由并获得相应授权。
- 阅读 [STATUS](management/STATUS.md)，按任务读取 [DECISIONS](management/DECISIONS.md) 中相关决策；用 [README](README.md) 定位主题，只加载所需资料。
- 判断本次是内容新增、已有内容更新、事实核验还是结构调整。多阶段工作先列简明计划，再执行至验收完成。
- 只有重大歧义妨碍正确执行时询问具体问题；非关键选择采用合理默认并在报告中说明。
- 每个云任务已隔离，沿用现有检出，不默认创建 worktree 或嵌套 Git 仓库。

## 执行中

- 先搜索术语与同义词，优先更新已有章节；独立问题才新建章节，并维护索引、相关交叉链接。
- 简体中文为主，关键概念附准确英文；稳定英文文件名。产品、套餐、客户端和版本边界参照 [概念](docs/01-concepts.md) 与 [来源表](references/SOURCES.md)。
- 区分“官方文档已核验”“本次实测”“推荐实践”“本项目约定”“待核验”。未经验证的功能不得写成事实；官方描述不能冒充账号界面实测。
- 当前功能优先查 OpenAI/GitHub 官方资料；保留链接、核验日期、实际访问范围及失效条件。来源变化时检查受影响章节，不把新旧说法悄悄混用。
- 避免无意义重复、全库机械读取和过度工具化。专题流程放 docs/，可复制任务指令放 prompts/，文件骨架放 templates/。
- 不保存秘密或未授权私人材料。只检查凭据名称和存在状态，不打印值。不得绕过权限、签名或 TLS 校验。

## 执行后：每条独立任务必须留痕

1. 每完成一条独立用户任务，向 [TASK_LOG](management/TASK_LOG.md) 追加一条记录并提供执行摘要；单位是一次用户任务，不是终端命令。
2. 采用 [任务日志模板](templates/task-log-entry.md)：日期时间（Asia/Shanghai，含偏移）、目标、主要操作、文件、结果、验证及证据、问题和处理、未解决项、下一步。调查未改知识文档也须记录原因；未执行或未通过的操作明确标明。若用户明确要求完全只读，不擅自写日志，在回复中提供待追加记录并说明原因。
3. 检查 STATUS 是否需要更新；实质内容/结构变化才更新 CHANGELOG；长期决定才写 DECISIONS；新研究问题进 ROADMAP；新可靠来源进 SOURCES。避免复制同一段事实。
4. 运行与变更匹配的检查：文件与相对链接（含锚点）、索引可达、围栏、产品边界及来源核验；使用 [维护与检查](docs/09-maintaining-this-guide.md)。有代码的未来任务按其既有验证流程，不以零测试或纯格式检查冒充功能验证。
5. 检查全部本次新增文件正文和 `git diff`；未跟踪文件不在普通 diff 中。只暂存获授权路径，不使用笼统的 `git add .`。

## Git 与最终报告

有当前任务授权时可提交、推送工作分支、创建 PR；没有授权则保留可审查差异。不得把首版授权沿用为未来任务的永久推送权。未获额外授权不强推、不覆盖历史、不合并默认分支、不发布环境或部署。

报告按“任务目标／执行结果／文件变更／验证情况／未解决问题／下一步建议”组织；涉及 Git 时写实际分支、提交、推送结果和 PR 链接。没有发生的操作不得写成功。
