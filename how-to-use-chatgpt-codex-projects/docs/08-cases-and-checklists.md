# 8. 按场景使用案例与检查清单

前三个案例是**完整教学演练**，以常见需求设计，未在用户真实论文集或代码工程上运行；第四个是本知识库的实际建设记录。不要将设计的命令结果写成真实成功案例。

| 需求 | 案例 | 要观察什么 |
| --- | --- | --- |
| 学习、长期学术研究 | [课程与文献阅读](../examples/01-research.md) | 项目资料和正式研究结论如何分开 |
| 持续修改、测试代码 | [Python 工程维护](../examples/02-code-project.md) | 可复现输入、验收、失败诊断和分支 |
| 持续扩充个人知识库 | [知识库演进](../examples/03-knowledge-base.md) | 内容归属、去重、索引与来源失效 |
| 接手本库 | [本项目的实际示范](../examples/04-this-guide.md) | 正式文件、一次任务一条记录与真实验证 |

## 从案例迁移到你的任务

先用 [决策表](02-project-decisions.md) 选择工具，再复制对应的初始化片段，替换目标、路径和权限。只带入满足需求的文件；学习项目不必复制代码项目的部署程序，纯文档项目也不需要虚设“测试服务器”。

初始化时核对：目标和非目标可辨、材料可访问、正式来源唯一、敏感内容有边界、成功有可观察结果。执行时核对：读了相关状态、修改在范围内、来源支持当前说法、失败没被略过。结束时核对：文件确实存在、检查对应当前结果、日志如实、下一步可执行、提交/推送分开报告。

完整清单放在 [task-checklist](../templates/task-checklist.md)，不在各个案例重复同一套长清单。初次实践选一个可在一次任务内验收的小目标，例如“整理一篇文献并登记两条待核验主张”，比一次建成所有未来模块更能暴露真实问题。

## 如何判断实践有效

可观察三个指标：恢复任务时能否找到下一步；关键结论能否回到来源；同一事实是否只需更新一处。指标是本手册提出的观察方法，没有经过用户长期对照实验验证。首次任务完成不代表跨日恢复、多人并行和所有套餐均已实测，应把这些试用记录到具体任务日志。
