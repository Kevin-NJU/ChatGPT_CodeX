# 6. 执行、跨日恢复与失败处理 SOP

目标是让新会话接手一个可观察状态，而不是猜上一轮发生了什么。本章是推荐实践；其中逐任务日志是 [本项目约定](../AGENTS.md)。环境可复用与每任务独立工作区依据 [O6](../references/SOURCES.md)。

## 标准执行流程

| 阶段 | 行动 | 完成信号 |
| --- | --- | --- |
| 初始化 | 确认仓库/权限、目标与非目标；按规模创建入口、必要状态及资料索引 | 新人能找到目标、正式资料、下一步 |
| 定义任务 | 拆分可验证阶段，列修改范围、依赖与验收 | 知道什么结果算完成，什么必须停下 |
| 读取上下文 | 看工作区差异、适用指令、STATUS、相关决定与材料 | 分清当前事实、旧计划和未知信息 |
| 执行 | 先维护现有内容，单独分支，频繁检查范围 | 每项改变对应任务目标 |
| 验证 | 检查产物实际存在、功能或文档结构、来源与异常差异 | 给出本次目标的证据，失败有诊断 |
| 落盘 | 追加任务日志；按必要性更新状态/决定/路线图/变更 | 下一会话可接手，无虚构完成项 |
| 交付 | 展示差异、验证和限制；按本次授权提交/推送/PR | 用户知道本地与远程分别有什么 |

## 跨日期与跨设备恢复

1. 使用同一个正式来源：仓库远程与具体目录；确认是哪台机器/哪个云任务。查询当前分支和 HEAD，不复用旧日志中的值。
2. 先看 `git status --short --branch`。有未提交改动就先阅读与保留，不自动 pull、切分支或 reset。
3. 需要远程同步且具备网络权限时先 `git fetch origin`，比较目标分支；干净且确认应跟随远端的本地分支才考虑 `git pull --ff-only`。不要把本地专有提交当垃圾清理。
4. 读 STATUS 的下一步，追溯关联任务/决定；若文件与实际仓库不一致，先报告并修正记录，不机械续写。
5. 运行与下一步相关的最小验证，确认环境仍可用；进程需重启，凭据需当前有效。
6. 简短复述“已确认状态／本次目标／未知项”，继续执行。使用 [恢复提示词](../prompts/03-resume-work.md)。

换到 Windows 或另一设备，不假定 `/workspace` 路径存在；先定位实际检出。Git 不运输未跟踪文件、忽略文件和运行进程；迁移必要的非秘密材料应单独安排。账号内聊天同步也不会同步这些内容。

## 多会话并行与分支

并行前分配文件所有权、分支与合并顺序，尽量让会话修改不同文件；共享 STATUS/TASK_LOG 指定最终整合者。两个会话在同一工作树同时切分支、提交或改同一日志，容易产生难以归属的差异。独立云任务可各用现有检出；本地确有并行需求再选择 worktree（O10），每个分支仍需检查和集成。

分支创建示例是 `git switch -c docs/<topic>`，需将 `<topic>` 替换成短主题；只在已确认目标工作树中执行。暂存用具体路径，提交前看 `git diff --cached`；推送工作分支，PR 负责评审，默认分支合并另需授权（G3）。

冲突处理：先保留双方工作 → 阅读冲突双方的目标、基底和证据 → 对内容含义做合并 → 删除冲突标记 → 跑受影响检查 → 更新状态/日志 → 再提交。不能盲选 ours/theirs，尤其不能把两份各自正确的任务日志覆盖成一份。

## 失败、回滚与恢复

- 检查失败先记录命令、错误范围与环境，区分“工具不可用”“权限不足”“内容错误”；每次重试都应有新诊断或条件变化。
- 操作错了但未提交：先审查差异并复制需保留内容，只撤销自己明确造成的改动；不要用 `git reset --hard`、`git clean -fd` 作常规恢复。
- 错误已提交且共享：在授权范围内优先用反向提交 `git revert <已确认提交>` 保留历史，再验证；它也可能冲突，不能盲执行。
- 未共享的错误提交：先保留分支/备份和具体证据，再考虑局部重做；不擅自重写用户历史。
- 密钥误入历史：先吊销/轮换，在不泄露值的前提下报告影响，再由用户授权历史清理。删除当前文件不消除历史泄露。

## 阶段总结、暂停和重启

每个里程碑记录成果、证据、限制和下一阶段条件，不把任务日志全文搬进 STATUS。暂停时写明最后有效状态、未完成清单、必要资料位置及重启步骤；归档时保留导航与“已归档”标识，先核对保留要求再删文件。重启时重新核验易变化产品说明和环境，而不是因旧版“通过”就继续宣称适用。

完成前可直接用 [检查清单](../templates/task-checklist.md)；复盘与交接分别见 [复盘](../prompts/07-retrospective.md) 和 [迁移](../prompts/08-handoff.md)。
