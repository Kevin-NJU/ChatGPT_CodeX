# 4. 上下文、记忆与文件：能延续到什么程度

实际需求是隔天或换设备后继续做事。风险在于把“能访问旧聊天”误认为“每个细节都在当前模型输入中”，或者把临时会话结论当成已更新的正式文件。本章官方事实依据 [O1、O2、O6、O7](../references/SOURCES.md)，核验日 2026-11-01；管理建议另行标明。

## Context Window 不是无限历史

上下文窗口（Context Window）是一次模型处理可容纳的信息范围，以 token 衡量；当前指令、消息、检索材料、工具输出等会占用相应资源，具体分配由模型和产品决定。不同模型及入口的窗口不同，不把某个 API 参数套给所有 ChatGPT 会话。O2 当日写明 GPT-6.1 Sol 在 Work/Codex 默认窗口为 500,000 tokens；这是带型号与入口的当日文档值，不是所有项目的永久上限。

长会话可能压缩上下文（compaction）、检索部分旧内容或省略细节。压缩摘要可以保留方向，但不适合当作原始实验参数、逐字授权或完整证据。O7 明确记忆不会保留每次对话的所有细节；“历史可用的信息无独立存储上限”也不等于“当前上下文无上限”。关键参数应回原文或文件核对，不从模型自信语气判断是否记对。

## 项目记忆边界矩阵

下面是 O1 当日说明，仍依赖记忆设置、工作区政策、套餐和功能开放情况；“可引用”不承诺每次都会引用。

| 模式/范围 | 个人已存记忆 | 同项目其他聊天 | 项目外聊天 |
| --- | --- | --- | --- |
| Project-only memory | 不引用先前个人已存记忆 | 可以引用 | 双向隔离：不引用外部，外部也不能引用该项目聊天 |
| Default memory：Enterprise/Edu | 可按设置引用 | 可以引用 | 项目聊天仍受项目内边界约束，双向不引用项目外聊天 |
| Default memory：其他套餐，含 Business 私人项目 | 可按设置引用 | 可以引用 | 可以跨项目/普通对话引用，但不得越过对方的 project-only 边界 |
| 共享项目 | 自动使用 project-only | 可以使用项目内资料与聊天 | 不引入个人成员在项目外的记忆、上下文或自定义指令 |

设置要求：O1 当前说明，若界面只有 Enable memory 应开启；若有分离开关，Enterprise 需个人 Reference saved memories 及工作区允许 memory，其他订阅需 Reference saved memories 和 Reference chat history。组织策略可进一步限制。不要把“我看到了项目”当作记忆已正确启用。

**设置可变更性：** 当前 O1 允许在项目设置中切换 Default / Project-only；修改可能数小时后生效。共享项目不能切回 Default；取消共享也不解除 project-only。切为 project-only 后聊天和文件仍在项目内，相关信息从项目外使用的记忆移除。旧教程“只能创建时选择”不适用于本次核验版本。Project-only 当前不提供 Work；希望使用 Work 时先判断隔离需求，不能只为了入口方便而降低数据边界。

个人记忆用于个性化；项目记忆用于该项目可用的相关资料。这些都不是按事务写入、字段完整、可校验的项目数据库，也不能代替备份。

## ChatGPT 与 Codex 之间怎样共享

| 交接途径 | 已有能力或前提 | 不能据此推断 |
| --- | --- | --- |
| ChatGPT Project 内的 Chat / 支持的 Work | O2 说明可用项目上下文，受 O1 模式限制 | Codex 独立视图自动得到所有项目聊天 |
| Cloud Work 跨 web/mobile/desktop | O2 说明云 Work 聊天同步 | 本地目录、进程或 Codex 桌面历史也成为同一份云数据 |
| Codex Cloud 跨入口继续 | 当前文档支持 web/mobile/desktop 继续云任务 | 新建任务自动加载上个任务所有未提交文件 |
| Git 提交后推送、另一端 fetch/检出 | 有远程权限，且操作实际成功 | 仅本地 commit 就能在另一设备获得内容 |
| 显式交接摘要与文件 | 指定路径、版本、必要资料且实际可访问 | 模型仅凭同名项目知道完整仓库 |
| App/插件读取共享来源 | 工具存在、身份和目标权限正确 | 接入账号即持续镜像所有文件；O1 特别说明项目内 Google Drive 不预先同步检索内容 |

Codex 新任务先确认目录、分支/HEAD 和工作区差异，再读适用 AGENTS、STATUS、相关决定及主题文件。若状态来自旧提交，先比对差异；不让旧快照盖掉新任务事实。新任务复用环境设置与每任务独立工作区是 O6 的当前描述，不能解读为共享一个不断更新的磁盘。

## 为每条重要信息标明持久化状态

- **已持久化**：文件存在并已核对内容；进一步注明“仅磁盘”“已提交”“已推送”。不同层级不能混写。
- **会话临时信息**：刚讨论的建议、计划或工具输出，尚未写入正式文件。
- **推断**：AI 根据现有材料补出的解释或可能原因，须确认依据，不能冒充用户决定。

推荐交接写法：“正式范围见 `management/STATUS.md`；决策 D002；本地 HEAD 为实际查询值；只推送过哪些分支；当前有何未提交差异；最后通过的检查是什么；下一步是什么”。运行中的服务还需记录重启命令和就绪验证，PID 不具备迁移意义。

跨日与跨设备的实操见 [恢复 SOP](06-execution-recovery.md) 和 [继续工作提示词](../prompts/03-resume-work.md)。
