# 5. 长期指令与单次任务怎样分工

重复贴一大段“请认真负责”并不会明确修改权限。有效指令要能回答：适用于谁、在哪些路径、何时触发、怎样验收。官方机制依据 [O1、O3、O4、O5](../references/SOURCES.md)，以下编写方式是推荐实践。

## 三个层次

- **长期约定**：稳定的边界、事实核验规则、任务日志义务、Git 授权要求；写在 AGENTS 或 ChatGPT 项目设置。
- **单次任务**：本次目标、输入、允许修改路径、具体产物和完成条件；用 prompts/ 中的任务入口。
- **专题程序**：只有特定工作才需的操作细节，放对应 docs/ 或有明确用途的 skill；不要塞满 AGENTS。

ChatGPT Project Instructions 只在相应项目生效，O1 说明其覆盖全局 custom instructions；它不是任意覆盖安全规则和工具权限的入口。AGENTS 是 Codex 的文件指令机制；把它上传到 ChatGPT 不会自动触发同样的文件发现过程。

## AGENTS.md 的发现、继承与覆盖

按 O5 当前文档：启动时构建指令链；全局层在 Codex home 中优先选择非空 AGENTS.override.md，否则 AGENTS.md。项目层从项目根（通常 Git 根）到当前目录逐层查找；每层优先 AGENTS.override.md，再 AGENTS.md，再配置的 fallback 文件名，每目录至多一个。靠近当前目录的指导在合并后更靠后，可覆盖前面的适用指导；这不赋予越过系统、开发者、当前用户要求或真实权限的能力。

当前文档默认合并大小上限为 32 KiB（project_doc_max_bytes 可配置）。不要依赖无限长度或把关键边界埋在末尾。不同入口的发现时机和呈现方式可能不同；本项目在子目录，**从仓库根启动时，显式要求读取本目录 AGENTS，或将任务目录设为本目录**，不能假定所有子目录规则都已自动加载。

本项目 AGENTS 只管本目录，不据此要求修改兄弟项目；当前任务授权提交首版，也不代表以后每次都可推送。对于真正冲突，指出来源及影响，保留安全且符合上层要求的路径；不要用多份“最高优先级”声明解决冲突。

## 错误示范与可执行改写

| 常见写法 | 改进版本 | 原因 |
| --- | --- | --- |
| “记住所有内容，每次读完整仓库” | “读 STATUS 与本任务相关章节；追溯决定时查 DECISIONS” | 明确检索入口，减少无关上下文 |
| “自动修好所有问题” | “只改指定目录；修复本次引入的问题；额外问题写入建议” | 防止扩大范围和混入无关变更 |
| “修改前任何操作都问我” | “可执行本任务必要的可逆本地操作；外发、部署、合并按授权执行” | 给足已授权行动空间，保留真实决策边界 |
| “测完告诉我都好了” | “报告执行命令、目标、退出结果、证据路径和未运行项” | 可复核，而非只听完成宣称 |
| “产品功能写得完整一点” | “优先官方资料，记日期和范围；不能确认则写待核验” | 完整性不能以编造填空 |
| “每个操作都写日志” | “一次独立用户任务一条日志；命令归入主要操作和验证” | 保留可用历史而不制造噪声 |

## 简洁任务契约

可采用 [任务执行提示词](../prompts/04-execute-task.md)：写清目标、输入版本、允许/禁止路径、验收和 Git 授权，再让 AI 做所需检查、修复及复验。重要任务要求“直到验收完成或出现具体外部阻塞”，避免首版生成后就停止；同时不把“持续工作”误写成无限扩展主题。

发现错误时先核对证据、区分环境与内容问题，修正相关页面并记录影响。可复用经验进入现有指南；一次性失误只记任务日志；确有长期价值才升级到 AGENTS。O3 的多文件 harness 是官方示例工作流，O4 提醒按需读取、精简指令；二者都不要求每个个人项目建立完整工程框架。

可复制的长期指令见 [ChatGPT 模板](../templates/chatgpt-project-instructions.md) 与 [AGENTS 模板](../templates/agents.md)，不要连模板中的方括号变量都原样当成正式规则。
